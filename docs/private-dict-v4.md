> - **2026-11-21 更新**：统计页只保留私人结构；本文里的「公共归属」只指母树绑定 / 对照，

>   （旁支推荐）；③快速语义校验。公共报表只是它的一个消费者。

## 零、一页结论

| 维度 | 旧（v3） | v4 |
|---|---|---|
| 层级 | `[树]` 缩进 **和** `[会计]` 的 `@父码` | 会计类型 → 统计分类 → 节点 |
| 绑定写在哪 | 每个节点一行 `^SYS...`（81 条） | 节点级固定绑定，文末 `[母树]` 一块 |
| 节点行 | 13 个 token | `简码，名称`（2 列） |
| 分组是什么 | 带简码的节点（`g_daily`） | 用户自己的统计分类（无简码，不挂母树） |
| 备注 / 行为 | `@父码` 任意深度 | 归属 → 关键字，恰好两层 |
| 中英文 | 每行 `中文名 \| 英文名` + 双简码 | 固定列：第 3 列英码、第 4 列英文名 |
| 真实字典体积 | 229 行 / 9,610 字符 | 202 行 / 1,837 字符（24 分组 + 81 绑定） |

一句话：**会计类型是根，统计分类是用户分组，节点的母树绑定固定写在 `[母树]` 里。**

## 一、为什么旧结构「看着困难」（实测，不是感觉）

### 1.1 同一事实写了两遍

`local/private.dict.tv` 共 229 行，其中 **210 行是节点数据**，而节点只有 **105 个**：
`[树]` 一次、`[会计]` 一次。两处都能改父子关系，但**只有一处生效**。

实测（`source.compileDictSource`）：

```text
[树] 里「子」是根、[会计] 里写 @g1  →  编译结果 parent = ''    // @ 被静默忽略
删掉 [树] 那一行，@g1 生效           →  parent = g1
```

### 1.2 每个节点都背着一串机器路径

```text
node P 费用 steam BX bx 保险 | 保险 100 @g_charity sort:20 ^SYS.CAT.INSURANCE.GENERAL
```

105 行的逐项统计：`P`×105、形态×105、`sort:`×103、`100`×104、`@g_*`×81、
`^SYS.`×81、`| 英文名=中文名`×81、`英码=中码小写`×105。
**一行 13 个 token，属于用户的只有 3 个。**

### 1.3 根本原因：旧统计分类横跨母树多支

把 24 个旧私人分组按「子节点的叶子归属」分类：

| 旧分组 | 节点数 | 跨了几支 | 具体分支 |
|---|---:|---:|---|
| 日常 | 11 | **5** | 其他支出 / 餐饮 / 通讯 / 购物 / 居住 |
| 休闲 | 6 | **3** | 娱乐 / 医疗健康 / 旅行 |
| 生活 | 5 | **3** | 餐饮 / 居住 / 购物 |
| 网贷 | 7 | 2 | 消费贷 / 信用付A白条 |
| 信用 | 6 | 2 | 信用卡 / 消费贷 |
| 损失 | 5 | 2 | 其他支出 / 税费金融 |
| 公益 | 2 | 2 | 保险 / 人情社交 |
| 其余 17 个 | —— | 1 | 已经与某一支对齐 |

**24 个里有 7 个横跨多支。** 一个分组既然不对应母树的任何一支，
归属就只能落到每个节点上——这就是 81 条 `^SYS...` 的来源，也是「结构看着困难」的来源。

结论：**旧分组跨支不是错误**。最终设计不再要求分组对齐母树：
每个节点各自带一条固定绑定，写在文末 `[母树]`；分组保持用户原样。

### 1.4 程序会重排你的手稿

任何 GUI 结构编辑都走 `app.syncDictSourceAndCompile()` → `source.dictToSource()`：
按 `域+类型+简码` 重排、只写固定表头，**用户注释和空行全部丢失**。
你整理好的字典，点一次树编辑器就被重排。

## 二、三层，贯穿软件

```text
会计类型（6，固定）          费用 / 收入 / 资产 / 负债 / 成本 / 权益
  └─ 统计分类（名字可改）      日常 / 生活 / 餐饮 …        ← 用户自己的分组，不挂母树
       └─ 节点                地铁 / 储蓄招 …            ← 记账单位 + 固定母树绑定
```

备注 / 行为同构：

```text
归属（标签）        商品 / 商家 / 情绪
  └─ 关键字（有码）   咖啡 / 开心 …                      ← 记账单位
```

| 层 | 谁定 | 有简码 | 挂母树 | 报表角色 |
|---|---|---|---|---|
| 会计类型 | 固定 6 个 | 否 | 否 | 报表顶层、段头、筛选 |
| 统计分类 | 用户命名 | 否 | 否（纯分组） | 私人汇总 |
| 节点 | 用户 | 是 | **是（固定绑定）** | 记账明细；公共归属 |
| 归属 / 关键字 | 用户 | 归属否、关键字是 | 否（P0） | 简洁报表 / 细粒度 |

**术语统一**（贯穿 UI、文档、报表、筛选、候选）：
`会计类型`（不再叫「大类」）、`统计分类`（不再叫「组 / 分类」）、`节点`、`归属`、`关键字`。
代码里的字段名可以继续叫 `type` / `category`，但用户可见文案一律用这套词。

**语言不是一层**：每个条目带一对名字（中/英）与一对简码，缺英文回退并标缺失；详见 §3.9。

**母树层级 vs 私人字典**：母树层级只用于理解、推荐、导入；私人字典**不复制**它：
会计类型下所有母树分支/叶子平级可选，统计分类是完全独立的用户分类。

## 三、文本格式 v4

### 3.1 骨架

```text
// 注释
[费用]，Expense          ← 会计类型 + 英文名
日常，Daily              ← 统计分类：名称，英文名（纯分组，不挂母树）
  DC，点餐               ← 节点：简码，名称
  ZC，早餐
[备注]，Notes
商品
  KF，咖啡，Cof，Coffee
[母树]，Bindings         ← 节点级固定绑定
ZC，餐饮/早餐
DC，餐饮/外卖
```

- `[会计类型]` 这类段头是顶层；英文名可选，默认取系统英文。
- 段内两层：第 1 层是统计分类 / 归属，第 2 层是节点 / 关键字。
- **分隔符是中文逗号 `，`**：它占一个全角位，列之间自然隔开一个字符，读起来清楚。
  **英文逗号 `,` 也识别，输入或读入时自动归一成中文逗号**——所以名称里不能有任何逗号。

### 3.2 三种行的列

| 行 | 列 |
|---|---|
| 段头 | `[段名]` 或 `[段名]，English`（段名 = 会计类型 / 备注 / 行为） |
| 统计分类 | `名称` / `名称，英文名`（纯分组） |
| 节点 / 关键字 | `简码，名称` / `简码，名称，英文简码` / `简码，名称，英文简码，英文名` |
| 归属 | `简码，分支或叶子`（文末块，每个节点一条） |
| 归属 | `名称` / `名称，英文名` |
| 别名 | `alias 别名，目标1，目标2…` |

规则：

- 字段两端空格忽略；**空字段 = 省略**。只写归属不写英文名：`通勤，，交通`。
- **两种逗号都是分隔符**：`，` 是规范写法，`,` 在输入/读入时自动归一成 `，`
  （中文逗号占全角位，列间有一个字符的间隔）；因此**名称里不能出现任何逗号**，
  需要停顿用 `·` 或空格。编辑器里敲 `,` 立即替换成 `，`（光标不跳）；粘贴、导入、手改的文本在编译时归一。
- 简码：单 token，不能含空格或逗号；域前缀写在同一列：`C:ZHC，储蓄招`。
- 英文简码：单 token。
- 名称、英文名：可含空格，**不能含中英文逗号**。
- 列数超出上表 → 报错（例：节点 5 列 → 「节点最多 4 列；别名请用 alias」）。
- 没有自描述记号，所以**列的位置就是语义**；解析器靠列数 + 层级 + 段名判断行类型。

### 3.3 缩进：后台如何「识别准确」

1. 先规整：`CRLF → LF`；**tab → 2 空格**；**全角空格 U+3000 → 2 空格**；**英文逗号 `,` → 中文逗号 `，`**；
   **行首**出现 NBSP 等其它不可见空白 → 报错（避免「看起来对齐、实际不是空格」）；行内其它字符保持原样。
2. 缩进宽度 = 规整后的前导空格数；行尾空格忽略。
3. 用**栈**推断父级：每读一行，弹出栈中 `indent ≥ 当前 indent` 的项；栈顶即父。
4. `2/4/6` 与 `4/8/12` 等价；**任何更深 = 下一级**，不要求等宽。
5. 越级下缩（0 → 6）只算一级；回缩到不存在的层（0,4,2）→ 父 = 最近的更浅层（0）。
6. 注释行、空行不参与栈；段头清空栈。
7. **会计段恰好两层**：第 0 层必须是统计分类（无简码），第 1 层必须是节点（有简码）。
   第 0 层写成两列以上但第一列像简码 → 警告「这看起来像节点，是不是少缩进了？」；
   第 1 层第一列是中文 → 警告「这看起来像统计分类，是不是多缩进了？」；
   第 2 层及更深 → 报错。
   **备注 / 行为段恰好两层**：第 0 层归属，第 1 层关键字。
8. 段内第一条带缩进 → 警告「段内第一条不该缩进」，按根处理（不丢行）。
9. 移动一行时**子树跟着走**：子行缩进不变，仍比它深；
   除非你把父行缩进到与子行齐平——那它们就变成兄弟了（规则 3 的自然结果）。

> 判据：**多缩进一格 = 下一级，少缩进一格 = 上一级。**
> 不根据归属反推层级，也不根据上一行的名字猜——所以「后台识别」是可预测的。

### 3.4 绑定：节点级，写在文末 `[母树]`

```text
[母树]，Bindings
ZC，餐饮/早餐
BX，保险
ZHC，储蓄卡
```

- 一行 = 一个节点的固定绑定：`简码，分支或叶子`；值可以写名字、斜杠路径或 `SYS.` 全 ID。
- **只能在同一个会计类型里找**；目标可以是中间分支，也可以是叶子。
- 一个节点最多一条；重复写 → 报错。没写的节点 = 未绑定（公共报表记「未归类」）。
- 绑定**固定在节点上**：之后改简码/名称不动它；换统计分类也不动它。
  要改绑定，在节点编辑卡里选（会提示影响这一笔的公共归属）。
- 旧文本里统计分类的第三列（`通勤，Commute，交通`）仍能读：只当作**该分类的默认绑定**，
  子节点继承；写回时**落到每个节点**的 `[母树]` 行，不再输出分类第三列。
- 长路径不再出现在树体里，只在文末的小块里出现一次。

**实现备注**：编译产物里每个节点带自己的 `anchor_id`（固定绑定），
`calc` 用本地类型/分组算账，`publicReport` 按节点绑定上卷；两者互不覆盖。

### 3.5 真实样本（由 `local/private.dict.tv` 无损转换并校验，81/81 等价）

```text
[费用]，Expense
日常，Daily
  S，水
  ZC，早餐
  KC，快餐
  …
生活，Living
  MC，买菜
  DC，点餐
  …
[资产]，Asset
储蓄，Savings
  ZHC，储蓄招
  …
[母树]，Bindings
S，居住/水电燃气
ZC，早餐
ZHC，储蓄卡
…
```

**旧分组原样保留**（日常/生活/通勤/出行……），每个节点的母树绑定在文末，
共 24 个分组、81 个节点、81 条绑定；**没有任何信息被拆开或合并**。
改过名的才会出现，例如：

```text
通勤，Commute，交通
  DT，地铁
  GJ，公交
```

### 3.6 列定义

| 列 | 出现在 | 含义 | 缺省 |
|---|---|---|---|
| 1 | 统计分类 | 名称 | 必填 |
| 1 | 节点 / 关键字 | 简码（可带 `C:` 前缀） | 必填 |
| 1 | 归属 | 名称 | 必填 |
| 2 | 统计分类 / 归属 | 英文名 | 回退中文 |
| 2 | 节点 / 关键字 | 名称 | 必填 |
| 2 | 段头 | 英文名 | 系统英文 |
| 3 | 节点 / 关键字 | 英文简码 | 中码小写 |
| 4 | 节点 / 关键字 | 英文名 | 回退中文名 |

**不在文本里的字段**（全部可推导，见 §7）：

| 字段 | 处理 |
|---|---|
| 形态 `form` | 由会计类型推导（费用→蒸汽、资产→流体、成本→冰块、B 极→外部） |
| 权重 `weight` / 置顶 `pin` | 取消；候选排序按匹配质量 + 行序 |
| 标签类型 `kind` | 按名字推断（时间/增益/阻抑），P1 再谈显式覆盖 |
| 排序 `sort` | 行序 |

### 3.7 域

- 默认 P；`P/F` 与 `C/H` 物理拆文件，编辑器里可以是同一份合并文本。
- 简码列写 `C:ZHC` 表示 C/H 域；同码只在**同域**唯一。
- 跨域别名必须域限定：`alias 垫付，C:BX`。
- **alias 只写用户显式的 1:n**；自动别名（码/名称）不落盘。
  `alias X，X，X` 这种自我别名视为旧自动添加，发射时忽略。
- 拆分时统计分类按子节点的域归属；一个分类下同时有 P 和 C 节点时，两侧各留一份（层级不变）。

### 3.8 错误处理：一行坏，不连坐

```text
[费用]，Expense
餐饮
  DC, 点餐                  ← 英文逗号自动归一成 DC，点餐
  早餐                      ← 报错「条目要两列：简码，名称」
  ZHC，储蓄招，CMB，Savings，招行 ← 报错「节点最多 4 列；别名请用 alias」
未分类
  ZX，杂项                  ← 未映射的统计分类：公共报表记「未归类」
```

- 坏行留在文本里，gutter 标错、状态栏计数；
- 坏行不生成条目；它的子行按缩进挂到它的父级（不连坐、不丢行）；
- 引用坏行的流水行报 `UNBOUND_NODE`（不猜）；
- 其余行照常编译。

> 位置语法的代价：**少一个逗号 = 少一列**。所以列数、空字段、单 token 校验必须严格，
> 报错必须说「这一行要几列、第一列是什么」。
> 另一个代价：**两种逗号都是分隔符**，所以名称里一旦有逗号就会被切开；
> 这是文档约束，解析器无法区分「名字里的逗号」和「列分隔符」。

### 3.9 中英文

三条总则：

1. **语言是标签，不是节点，也不是域。** 一个条目一对名字、一对简码；不建「中文条」和「英文条」两个条目。
2. **中文必填，英文可选。** 缺英文就回退中文并标「英文缺失」——**不自动翻译、不假装成对**。
3. **切换语言只改显示**：不改树、不改归属、不改报表数字；字典文本不因切语言而改写。

固定列：

| 层 | 中文名 | 英文名 | 简码 |
|---|---|---|---|
| 会计类型 | 段头方括号里 | 段头第 2 列（默认系统英文） | —— |
| 统计分类 | 第 1 列 | 第 2 列；可选，缺省回退中文名 | —— |
| 节点 / 关键字 | 第 2 列 | 第 4 列；默认回退中文名 | 第 1 列中码；第 3 列英码（默认中码小写） |

```text
[费用]，Expense
日常，Daily                            ← 分组英文名由你写（旧分组转换时保留）
通勤，Commute
  ZHC，储蓄招，CMB，China Merchants Bank
  DT，地铁                            ← 英文名回退「地铁」并标缺失；英文码默认 dt
[母树]
ZHC，交通
DT，交通
```

**4 态投影**：简码/明文 × 中/英，取条目自己的名字与简码；母树推荐码只在创建时预填。

**自动英文化**：字典页「补英文」按节点的绑定，把母树目标的 `en_name`
和英文码写进第 3/4 列，中文逗号分隔：

```text
ZC，早餐，breakfast，Breakfast
ZHC，储蓄招，cmb，Debit Card
```

英文码的优先级：**手写第 3 列** > **内置账本码表**
（`js/core/en-codes.js`，231 条：银行/支付/居住/餐饮/交通/收入/负债/教育/娱乐/人情 + 英文名兜底；
招行→`cmb`、工行→`icbc`、交行→`bocom`、支付宝→`alipay`、房租→`rent`、地铁→`metro`、工资→`salary`…）
> **母树概念码**（仅当这个绑定下只有一个私有节点）> **私有简码**；
最后全局去重（重复加 `2`/`3`…），所以六个银行账户不会再都得到 `debit`。
采纳新节点时也会自动带上英文。

码表是**人工维护的确定性映射**，不是翻译器，也不联网；加词只改 `en-codes.js` 一行
（`['词|别名', 'code']`，越具体越靠前）。没有命中就走母树概念码或私有简码，不会瞎编。

注意：`en_name` 补的是**公共概念的英文名**，不是私人名的翻译——
`储蓄招` 的英文名仍是 `Debit Card`，只有码是银行专属的 `cmb`；
要私有英文名请自己改第 4 列。未绑定节点跳过，不会瞎填。

**现状与收益**：81 个叶子的英文名全是中文名复制、105 个英文码全是中文码小写。
v4 不再写它们，英文界面改为显示「英文缺失 / 英文简码未填」徽标，
直到你真的填了第 3、4 列。样本里没有英文名，因为真实数据里没有一个真英文名。

**实现要点**：编译时把回退值填进 `en_name` / `en_code`，同时记 `en_auto` / `en_code_auto` 标记，
UI 才能区分「真英文」与「回退值」；字典文本永远只存用户写的那一份。

## 四、绑定与报表

### 4.1 三种绑定状态

| 状态 | 条件 | 公共报表 |
|---|---|---|
| 已绑定 | 节点在 `[母树]` 有一行，且解析到同一会计类型的分支/叶子 | 归到该节点（分支或叶子） |
| 未绑定 | `[母树]` 没有这一行 | 「未归类」单列，不并进「其他」 |
| 失效 | 母树升级后目标不存在 | 保留原文本 + `stale_anchor` 警告，不擅自改挂 |

**绑定固定在节点上**：改简码、改名称、换统计分类都不动它；
只有显式在节点编辑卡里重选，才会改这一笔的公共归属。

绑定也是**语义元数据**：程序靠它理解「这个私有词到底指什么」。因此它有三个用途：

1. **语义理解**：同名/同义校验、搜索、后续本地模型的特征；
2. **旁支推荐**：选了一个分支后，推荐同一个父级下的其它分支/叶子
   （`siblingSuggestions`；采纳弹窗里以「同支推荐」列出）；
3. **快速校验**：`validateBindings` 检查未绑定、失效、类型不一致、名字更像另一支
   （确定性规则，不调模型；字典页「校验」按钮打开清单）。

### 4.2 报表：本地算账，母树做公共坐标

```text
私人报表（本地字典决定）          公共报表（按节点绑定上卷）
费用                             费用
├─ 日常        1,204.00          ├─ 餐饮        1,204.00
│   └─ 水        128.00          └─ 居住          128.00
├─ 生活          860.00
│   └─ 房租      860.00
```

- 私人报表：会计类型 → 统计分类（合计）→ 节点（明细）；
- 公共报表：每个节点按自己的绑定 → 母树祖先链上卷（可到分支或叶子，看你怎么绑）；
- 两个报表都只认节点记账；统计分类永不参与平账；
- 备注 / 行为同理：归属级合计，关键字级明细。

### 4.3 统计分类不是节点

没有 ID、简码、别名、余额、流水引用。因此：

- 不会污染 `sourceCodeMap` / `dictToSource` / 报表合计；
- 不会出现「空组残留」——文本里有就有，删掉就没；
- 想给分类挂一个可记账的汇总，就建一个真正的节点（有简码），把子节点放它下面。

## 五、录入流程：私有优先，母树兜底

### 5.1 状态机

```text
输入 token
  ↓
1 私有精确（简码 / 名称 / 别名，同域）
  ├─ 唯一命中 → 直接用
  ├─ 多个命中 → 候选列表（wx1 / wx2）
  └─ 未命中 ↓
2 私有模糊（前缀 / 包含）
  ├─ 命中 → 候选（不自动选）
  └─ 未命中 ↓
3 母树候选：名称 / 别名 / 商户默认分类打分，带分支路径
  ├─ 用户采纳 → 建节点（零表单），挂到对应统计分类下
  └─ 用户忽略 → 进候选队列 / 保持未归类
4 都没有 → 手动新建（名称 / 简码 + 选择统计分类）
```

- 母树**不参与**第 1、2 步的排序；输入满 2 字符后只占**最后 2 个名额**，供采纳；
- 母树只给建议、不自动写；
- 采纳 = 一次写入：输入的是母树简码/英文码时用母树中文名，否则用用户原词。

### 5.2 采纳即建 + 自动落位

用户点「采纳 餐饮 / 早餐」：

| 序 | 规则 | 例子 |
|---|---|---|
| 1 | 已有同名统计分类 → 放进去 | 已有「餐饮」→ 直接放 |
| 2 | 否则新建统计分类，名字取目标的**顶级分支**名 | 新建「餐饮」→ 放早餐 |
| 3 | 节点绑定 = 你选中的母树分支/叶子（固定） | 选 餐饮/早餐 → 绑到该叶子 |
| 4 | 采纳的是分支（如 交通）→ 绑定到分支，公共报表到分支级 | 选 交通 → 绑到分支 |

```text
写入两行（必要时）→ 餐饮
                     ZC，早餐
推荐码同域查重（ZC 被占则 ZC2），节点立即可用
toast：已建节点「早餐」[ZC] · 餐饮   [改简码]
```

这就是「后台把私有树建清楚」：不生成任何额外数据结构，只把行放到对的位置。
下一次编译，私人报表里就出现「餐饮 → 早餐」。

### 5.2.1 v4 不自动建行为项

- 未命中的行为/备注 token **不建对象、不写 `未分类`**，只给候选或报错；
- 自动建的标签只在内存里标 `auto:true`，发射时跳过，不落盘；
- **`未分类` 只在用户显式新建、且没有归属时出现**，不从母树/自动逻辑带入。

### 5.3 已有条目

- 命中的私有节点没有分类：**不新建**，由用户把它拖进某个统计分类
  （可以新建一个名为「未分类」的统计分类）；绑定不动。
- 换统计分类：移动行，**节点绑定不动**。
- 换公共归属：编辑**该节点**的绑定，只影响这一笔。

### 5.4 单输入框的输入流

| 输入 | 行为 |
|---|---|
| 行首空格 | 在空格前插入 `YYMMDD`（今天），立即推荐**转出**节点 |
| 原文编辑器空行 | 任意空行（包括中间回车产生的）行首空格同样插日期；提示复用同一套 `analyzeInput` |
| 转出推荐顺序 | 历史转出次数降序；**费用类最后** |
| 转出精确命中 | 保留原词并补空格，**继续推荐转出**；输入 `>` 后才切到转入 |
| `>`（双击空格） | 开始推荐**转入**节点；精确转入后补空格，**继续推荐转入**；金额开始后停止 |
| `<`（三击空格） | 才开始推荐**备注/标签** |
| 金额 | 精确转入后数字直接进金额；**第一个金额字符自动补空格**；金额开始后不再推荐节点 |
| 修正模式 | 不在框首提示；只有光标定位到**波浪线错误行**才进入 |
| 输入框 | `>` 提示已隐藏；桌面 340px / 手机 300px，左右留边 |
| 输入满 2 字符 | 附加**母树匹配**，固定占推荐名额的**最后 2 个** |
| 候选选择 | 鼠标 / `↑↓` / `Tab` / `Enter`；**不再用 1–9 编号**，数字留给金额 |
| 母树采纳 | 建私有节点 + 固定绑定；输入是简码/英文码时用母树中文名 |
| 层级偏好 | 按历史节点的绑定深度（每个顶级分支取众数），同层母树候选优先 |

转出/转入用量都只看当前账本（`S.domain`）的历史事件；没有历史时退回原有排序。
母树层级只影响**推荐顺序与理解**，不改变私人字典的扁平结构。

底部输入框是气泡，原文编辑器是 CodeMirror 提示；两者都调同一个 `analyzeInput`，
所以用量排序、费用最后、母树最后 2 个名额、节点后继续推荐/金额后停止完全一致。
编辑器里选中母树候选会先插占位符，采纳后换成私有简码。

**批量录入**：`wx > s sc mc 3 6 12` 提交后**立即拆成 3 行源码**并落成 3 条流水（同一转出，三个转入，金额依次对应）；组合原文不保留，切换明文/掩码仍是这 3 行。原文编辑器里输入组合行后按回车也会原地拆成 3 行；Ctrl+Enter 或切模式前会先拆再编译，不会叠行；补全浮层开着时回车也优先拆整行；回车后立即按当前模式显示（不再等 260ms 防抖；单行实测约 29ms）（明文态就是明文，掩码态就是简码），不等切换模式。
多个转出/多个转入数量相等时逐个配对；金额只有 1 个时每笔都用它。
输入流：日期后每输入一个转出 + 空格，继续推荐转出；`>` 后每输入一个转入 + 空格，
继续推荐转入；一旦开始输入金额，节点推荐停止。
**多层组合输入的完整规范**见 [`multi-input.md`](multi-input.md)。

**极客语法糖**：金额阶段气泡上方提示 `金额 2/3 · 可 * 循环 / 100/ 均摊`。

- `wx > s zc dt 1 2 *`：空格隔开的 `*` 循环填满，三笔为 `1, 2, 1`。
- `wx > s zc dt 1 2*`：`*` 贴住最后一个金额，前几笔按序，之后全部用 `2`：`1, 2, 2`。
- `wx > s zc dt 100/`：总额均摊，三笔为 `33.34, 33.33, 33.33`（分位余数给前面几笔）。
- `wx > dc zc s dt 1 9/`：前 1 笔 1，剩余 3 笔均摊 9 → `1, 3, 3, 3`。
- `wx > dc zc s dt 1 9*`：前 1 笔 1，剩余全部用 9 → `1, 9, 9, 9`。
- 记录数 = 转入目标数（或配对笔数），不固定；4 个目标就是 4 条，`1 9 *` 为 `1, 9, 1, 9`。
- 批量中任一笔解析失败，整行都不落账，避免只写半批。
- `wx > dc 3 *m` / `*d` / `*y`：当前笔照常入账，同时往 `[PLAN]` 固定表加一条周期计划；
  固定页可直接改状态、金额、周期，改完自动生效。

**数字开头的简码**：`58D`、`消费贷58` 在节点位（日期后、`>` 后第一个词）优先当节点，
不按「58 天」金额处理；`>` 后的节点之后再出现数字才是金额。

**明文/掩码切换是纯投影**：不重新编译、不重算统计，只换编辑器文本；
CODE/PLAIN 两版按模式+语言缓存。1000 行、4× CPU 降速实测：
点击处理 1.9ms，首次切到明文 70ms，切回 35ms；3000 行首次切 71ms
模式/语言保存在本机 localStorage；进入账本时按保存的模式重投影，
按钮文字与源文本不会错位（旧版本存了明文但默认显示「掩码」会导致一次切换看似无效）。
（改动前 1594ms）。CodeMirror 是单一文本源，无法像列表那样用双 span 纯 CSS
切换，所以这里用“缓存投影 + 不重编译”达到同样的即时感。
底部气泡不再显示左侧 `>` 提示符；拖动时按气泡实际宽度夹紧，
气泡左边不会越过屏幕左缘（窄屏 320px 实测 left=8px）。

### 6.4 手稿保护

| 动作 | 现在 | v4 |
|---|---|---|

**行号区**：不再有删除/警告按钮；移动端整条行号栏可轻点（不要求点中数字），上下拖动超过 12px 视为滚动、不弹菜单；问题行只把行号染成橘红 `#ff7a45`；
行号固定 **5 位数字宽**（更窄的内边距），点击行号弹出：
删除 / 剪切 / 复制 / 粘贴 / 插入 / 上移；再点同一行号取消选中。波浪线仍然保留，用于定位具体错误。末尾留白为深色 30 行空间，不占行号。

- **粘贴** = 用复制内容替换选中行；**插入** = 在选中行上方插入复制内容；
- **上移** = 与上一行整行交换。

**简码重复**时，同码的两行行号都会标成橘红（第一行只染行号，不改正文颜色）。
菜单为**横排**，放在行号栏右侧、选中行的上方或下方，不会压住该行行号。
「上移」只交换整行位置，保留行尾换行，不会把两行拼成一行。

行菜单的剪切/复制会写入应用内行缓存；粘贴优先用这份缓存，
只有浏览器**已经授权** `clipboard-read` 时才读系统剪贴板，所以不会弹权限框、
也不会被权限框阻断。要粘贴系统剪贴板里的任意文本，仍可用 `Ctrl/Cmd+V`。

**改字典 → 流水跟着变**：字典条目在运行图里有唯一随机 ID；改名称/简码后

简码变化也会把流水里的旧简码换成新简码。
运行时 ID 每次编译重新生成；跨编译的稳定 ID 需要额外的持久化 ID 映射，尚未做。

**字典标题配色**：会计类型 `[费用]` 整段标黄 `#D7BA7D`，后面的英文名（`Expense`）调灰 `#8f8f8f`；`58D`、`消费贷58` 这类数字开头简码按普通节点码上色，不再按数字/金额染色。

**颜色与字号**：顶栏「设置」可改 8 类颜色（无效/未识别、行号、问题行号、日期、
节点、运算符、金额、备注）和字号 11–22px；修改密码也在这里。
这些只存本机 `localStorage`，不写账本；颜色用 CSS 变量实时生效。

**末尾留白**：流水和字典正文后保留 30 行高度的滚动留白；
它不是正文行，不写进源码、不占行号，只让内容能继续向上滚。
每次进入「流水」页会把最后 10 行放到视口顶部，末尾留白留在下方；正文不足一屏时从顶部显示。删除行会保留删除前的 scrollTop，不产生上下滚动位移。

### 6.5 危险操作

| 操作 | 影响 | 防护 |
|---|---|---|
| 改简码 | 流水源码按简码解析 | 统计引用数；>0 要求确认 + 批量改码 |
| 改节点绑定 | 只影响这一个节点的公共归属 | 提示目标分支/叶子 |
| 改统计分类名 | 不影响任何绑定 | 只提示重名 |
| 删统计分类 | 子节点上提一级（变未分类） | 确认 + 子节点数 |
| 删节点 | 有引用时拒绝 | 现有行为保留 |

### 6.6 语法机制：识别成功才生效

字典和流水用**同一套机制**，只是语法不同：

```text
词法（CM5 mode）   认出形状：注释、段头、逗号、数字、alias
   ↓
语义（编译）       认出含义：定义？链接？未知？
   ↓
生效（图）         语义成功的行才进数据；失败的行留在文本里，不参与计算
   ↓
视觉（overlay）    生效=亮，链接=青，未识别=灰白，坏行=波浪线
```

| token | 语义角色 | 生效条件 | 视觉 |
|---|---|---|---|
| 段头 `[费用]，Expense` | 会计类型 | 六类之一 | 蓝 `#4FC1FF` |
| 统计分类名 | `def` | 同类型内唯一，第 0 层 | 亮 `#D4D4D4` 600 |
| 节点 / 关键字简码 | `def` | 同域唯一，第 1 层，列数正确 | 亮 `#D4D4D4` 600 |
| 节点 / 关键字名称 | `def` | 非空、不含逗号 | 亮 |
| 英文简码 / 英文名 | `def` | 英码单 token；英文名可含空格 | 亮 |
| 归属（统计分类第 3 列） | `link` | 同类型母树里解析得到 | 青 `#4EC9B0` |
| `alias` 目标 | `link` | 目标码存在 | 青 |
| 解析不到的归属 / 别名目标 | `unknown` | 失败 | 灰白 `#B9C2CE` |
| `alias` 关键词 / 注释 | keyword / comment | —— | 紫 / 绿 |
| 坏行 | `error` | 列数、缩进、重复失败 | 灰白 + 波浪线 + gutter ✖ |

**「生效」的精确定义**（与 §八 对应）：

- 统计分类：进入编译后的树，能当节点父级；
- 节点：拿到 ID，能被流水引用，进余额与报表；
- 归属：分类的 `anchor_id` 有值；
- 别名：解析到目标；
- 否则：**只是文本**——不生成任何图元素、不参与报表，
  它的子行按缩进挂到它的父级（不连坐、不丢行）。

**与流水完全同构**：

| | 流水 `ledger.tv` | 字典 `dict.tv` |
|---|---|---|
| 成功 | 生成 `E_` / `B_` / `X_` | 生成节点 / 分类 / 别名 |
| 失败 | 保留 `X_` 文本，不计算 | 保留原行文本，不生成 |
| 视觉 | 已识别亮 / 已解析青 | 同上 |
| 状态栏 | 错误行数 | 生效行数 + 未生效行数 |

**实现**：`compileAll` 返回 `tokens: [{ file, line, from, to, role }]`；
编辑器按区间染色（CM5 `markText`，不引额外 addon），文本一改就清空语义层、
260 ms 编译后再回来——**宁可短暂无高亮，也不显示过时的识别结果**。
状态栏的「N 行生效 · M 行未生效」与流水的错误计数同一套口径。

## 八、不变量

1. **三层固定**：会计类型（6）→ 统计分类 → 节点；备注/行为：归属 → 关键字。
2. **会计类型不可增删**；新增类型要改模型，不是改字典。
3. **统计分类无简码、名称同类型唯一**；它不是节点，不能记账。
4. **绑定只写在 `[母树]` 块（节点级）**；统计分类不挂母树。
5. **绑定目标必须是同一会计类型下的母树节点**（分支或叶子）。
6. **缩进是层级的唯一来源**；不写 `@父码`。
7. **两层上限**：会计段第 0 层统计分类、第 1 层节点；备注/行为第 0 层归属、第 1 层关键字。
8. **列的位置就是语义**：顺序固定，不能调换；空字段用连续逗号跳过；
   `,` 与 `，` 等价，输出只用 `，`；名称里不含任何逗号。
9. **未绑定不猜**：没写 `[母树]` → 未归类 + 提示，不自动挑一个「最像的」。
10. **绑定失效不改挂**：母树升级后目标不存在 → 保留原文本 + `stale_anchor` 警告。
11. **记账只认节点**；统计分类只汇总。
12. **报表对账**：已归类 + 未归类 + 失效 = 私人合计。
13. **程序不重排手稿**：除显式「整理字典」外，编辑只做行级手术。
14. **坏行保留**：解析失败的行不删除，只在 gutter 标错。
15. **未识别即不生效**：解析失败的行只保留文本，不产生节点/分类/别名，不参与报表；
    识别状态与编译结果一致——同一份 `tokens` 驱动高亮与生效判定。
16. **术语统一**：用户可见文案只用 `会计类型`、`统计分类`、`节点`、`归属`、`关键字`。
17. **一个条目一对标签**：中文必填、英文可选；缺英文回退并标缺失，不自动翻译；
    切语言不改树、不改归属、不改报表数字。

### 9.1 读旧写新

| 旧 | 新 |
|---|---|
| 旧分组节点（`g_daily` 等 24 个） | 变成统计分类**标签**，名字/英文名原样保留 |

- 旧文本里的分类第三列（如果存在）只当默认绑定，写回时落到节点。

### 9.3 备注 / 行为

`@父码` → 缩进；两层。旧标签的 `kind` 保留为推断结果，不再写进文本。
旧归属（带码）→ 新归属（标签，无码）：**这是一次语义简化**，报表的「归属」层从标签对象变成字符串标签。

## 十二、风险与代价

1. **旧分组被重画（最大代价）**：日常 / 生活 / 休闲这些横跨多支的分组无法保留为一支，
   必须拆开。账本尚未启用，可以接受；但「日常」这类有感情的命名会消失或变成别支的名字。
2. **公共报表从叶子级降到分支级**（52 → 25 桶）。要更细就拆统计分类、
   或让某个分类映射到更深的母树叶子（如 `保险·医疗险`）。
3. **位置语法少一个逗号就少一列**：靠列数、空字段、单 token 三条校验兜底，
   再加两条「像节点 / 像分类」的缩进提示。比标记语法更依赖规范。
4. **名称不能含任何逗号**：两种逗号都是分隔符，所以中文名里的停顿用 `、` 或 `·`，
   英文名里的停顿用空格或 `·`（`China Merchants Bank, Ltd` 要写成 `China Merchants Bank Ltd`）。
5. **同名即归属**：给统计分类起名时可能意外对上母树分支。改名即解除，且编辑器会提示重选。
6. **缩进误操作**：多一个空格就多一级（这是规则，不是 bug）。
   缓解：缩进参考线、`←/→` 按钮、`整理字典` 统一缩进、树面板可拖。
7. **两层上限**：想建三层结构的用户会被拦住；这是为报表简洁付的代价。
8. **高级字段不再进文本**：形态由类型推导、权重/置顶取消（排序 = 行序）、
   标签类型按名字推断。这是「表格干净」的代价，P1 若需要再加显式覆盖。
9. **改统计分类归属影响整组**：必须提示影响节点数，不能静默。
10. **简码仍是危险操作**：只能靠确认 + 批量改码兜底。

### 固定收支备注的英文简码 / 掩码

`[备注]` 里这三条可写成四列（简码，名称，英文简码，英文名）：

```text
[备注]
固定收支
  FQ，分期，INST，Installment
  GDD，固定每日，FD，Fixed Daily
  GDM，固定每月，FM，Fixed Monthly
```

只写两列时，v4 也会自动补：

| 中文名 | 中文简码 | 英文简码 | 英文名 |
| --- | --- | --- | --- |
| 分期 | FQ | INST | Installment |
| 固定每日 | GDD | FD | Fixed Daily |
| 固定每月 | GDM | FM | Fixed Monthly |

掩码模式下备注里的标签名会换成简码（中文掩码用 GDM，英文用 FM），明文模式保持中文。

### 备注段颜色 / 简码判重

字典编辑器里 `[备注]，Notes` / `[行为]，Behavior` 段会单独着色：归属、简码、中文名、英文列各有颜色。

简码判重按 **节点 / 备注标签 / 行为项** 三类分开；备注标签 `HF，话费` 即使节点里也有 `HF`，仍显示 `HF`，不会变成 `HF2`。

## 下一步：私人字典 ↔ 节点树自动粗绑定

导入 / 编译私人字典时，按「精确码名 → 拼音/英文缩写 → 会计类型约束 → 同级唯一」生成节点树候选：

- 精确唯一：绑定到叶子；
