# 私有字典简化 · 研究结论（未实现）

> **2026-11-18 更新**：本文 §二~§八 已被 [`private-dict-v4.md`](private-dict-v4.md) 取代。
> 触发原因：用户裁决「字典可以不要树结构，只留用户确立的本地配置」，
> 随后逐步收敛为「**字典本体就是私有树**」，最终定形为三层：
> **会计类型 → 统计分类（唯一挂母树的一层）→ 节点**；备注/行为同构：归属 → 关键字。
> 私有树没有消失，只是不再单独写一段、不再和字段表各写一遍。
> 本文保留为研究过程与问题诊断的证据（§一的实测仍然有效）。
>
> 状态：**只做了研究，没有改代码，也没有迁移数据。**
> 目的：把私有字典从“每行 10+ 字段的源码”压缩成 NT 式可读表，
> 同时不破坏现有图模型、锚点和公共报表。

## 一、问题不是图论，而是表面表示

当前私有字典一行：

```text
node P 费用 steam BX bx 保险 | 保险 100 @g_charity sort:20 ^SYS.CAT.INSURANCE.GENERAL
```

用户真正需要填的只有：

```text
简码   名称   类型   分类
BX     保险   费用   公益
```

其余字段都是内部/派生/可选：

| 字段 | 应如何处理 |
|---|---|
| `P` 域 | 默认 P，不显示 |
| `steam` 形态 | 由类型推导，不显示 |
| `bx` 英文码 | 默认由简码小写生成 |
| `保险` 英文名 | 可选，默认留空 |
| `100` 权重 | 默认 100，不显示 |
| `@g_charity` 父组 | 改成“分类”列，虚拟分组 |
| `sort:20` | 可选排序 |
| `^SYS...` 锚点 | 可选“公共归属”，只显示短路径 |

结论：**复杂度是表示层的，不是模型层的。** 不需要推翻图模型，只需要换编辑/展示投影。

## 二、目标模型：薄私有表 + 锚点映射

```text
PrivateRow {
  code,        // 用户简码，唯一（同域）
  name,        // 用户名称
  type,        // 六类之一
  category,    // 虚拟分类，不生成组节点
  anchor_id?,  // 确认后的母树叶子；可空
  sort?        // 显示顺序
}
```

图论上仍是：

```text
私有节点 F  --anchor-->  母树叶子 L(T)
```

但：

- `category` 是标签，不是顶点；
- 不要求 `g_daily` / `g_life` 这类真实组节点；
- 私有树默认只有两层：类型 → 分类 → 叶子；
- `anchor_id` 是唯一跨树关系；
- 公共报表只认 `anchor_id`，不读私有分类。

---

## 三、匹配流程：私有优先，母树兜底

```text
1. 私有简码 / 名称 / 别名
       ↓ 命中
   直接用私有节点

2. 私有前缀唯一
       ↓
   用私有节点

3. 私有未命中
       ↓
   查母树叶子 / 别名 / 商户默认分类
       ↓ 命中
   给候选，用户确认
       ↓
   创建私有节点，同时写 anchor_id

4. 都没有
       ↓
   候选 / 手动新建
```

要点：

- 日常录入先查私有表，常用词快；
- 母树是公共词典和分类先验，不是每次输入都遍历；
- 用户确认后才写锚点，未确认不写；
- 未归类单独展示，不静默塞进“其他”。

## 四、建议的表格列

普通模式只显示：

| 简码 | 名称 | 类型 | 分类 | 公共归属 | 排序 |
|---|---|---|---|---|---|
| ZC | 早餐 | 费用 | 日常 | 餐饮 / 早餐 | 10 |
| BX | 保险 | 费用 | 公益 | 保险 / 一般 | 20 |
| ZHC | 招行储 | 资产 | 储蓄 | 银行存款 / 储蓄卡 | 30 |

高级模式再展开：

- 英文名 / 英文码；
- 权重 / 置顶；
- 显式父级（覆盖分类）；
- 原始 `anchor_id`；
- 系统标记。

---

## 五、必须保留的边界

1. **P/C 分域**
   - 简码同域唯一；P/C 可同码；
   - 别名跨域必须限定。

2. **锚点只挂母树叶子**
   - 不能锚内部节点、商户、银行 facet；
   - 有历史时翻转极性要拒绝。

3. **公共报表对账**
   - 未归类 / 失效锚点单独；
   - 私人余额 = 已归类 + 未归类 + 失效。

4. **旧数据**
   - 当前账本尚未正式使用，可一次性迁移；
   - 迁移时把真实组节点折叠成 `category`，保留叶子的 `anchor_id` 和 `parent_id` 语义。

---

## 六、风险

- 锚点覆盖率下降：用户只填简码/名称，公共报表会出现未归类；需要显眼入口和批量补锚点。
- 虚拟分类与显式父级并存时，必须有明确优先级；建议“显式父级 > 分类列”。
- 英语名/权重/域被隐藏后，高级用户仍需要展开入口。
- 私有优先会带来更多私有歧义；查重、别名、合并不能省。

---

## 七、建议的落地顺序（未开始）

1. **只做表格视图投影**，不改数据：
   - 6 列；高级字段折叠；
   - 锚点显示短路径，不显示 `SYS...`。

2. **分类虚拟化**：
   - 私有表增加 `category`；
   - 组节点从“用户必须维护”降为“可选高级父级”；
   - 私有树按 `type + category` 动态生成。

3. **切换匹配顺序**：
   - 私有索引优先；
   - 母树 fallback / 建议；
   - 确认后写 anchor。

4. **迁移与验收**：
   - 旧私有组节点折叠为分类；
   - 锚点、公共报表、P/C 分域回归；
   - 确保“未确认不写锚点”。

---

## 八、验收标准（未来实现时）

- 普通用户只填 4 列就能建节点；
- 私有表不出现 `steam` / `fluid` / `@g_*` / `^SYS...` 长路径；
- 录入时私有简码优先命中；
- 私有未命中才建议母树；
- 未确认不写 `anchor_id`；
- 公共报表对账相等；
- 旧数据迁移后金额、事件数、锚点不丢。
